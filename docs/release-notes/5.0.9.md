# 5.0.9 릴리즈 노트

스토어에 올라가는 짧은 문안은 저장소 최상단 `RELEASE_NOTES.md` 의 `## 5.0.9` 절이다.
DeployBar 가 배포할 때 읽어 가는 것은 **그 파일 하나뿐**이므로, 문구를 고칠 일이 있으면
거기서 고친다. 이 문서는 무엇을 왜 고쳤는지의 기록과 심사·배포 메모다.

(앱 안 변경 이력은 `ChangelogView.swift` 의 `5.0.9` 항목, 저장소 기록은 `HISTORY.md`)

⚠️ **5.0.8 이 스토어에 나갔는지 먼저 확인한다.** 안 나갔다면 5.0.8 문안을 이 앞에 이어
   붙여야 한다. 사용자는 나간 버전에서 곧장 넘어오므로, 그 사이 버전에서 만든 것은
   한 번도 소개되지 않은 채 들어간다.

## 이번에 고친 것

### 하나. 넣고 나서 보낼 수가 없었다

> 怎么少了一个发送按钮？我在微信中，可以快速的加上短语，然后找不到发送按钮

문구는 키보드에서 넣는데 **보내기는 시스템 키보드에만** 있었다. 넣자마자 지구본을 눌러
건너가야 했으니, 넣어 준 시간을 나가는 데 다 썼다. 5.0.8 에서 지우기 키를 넣은 이유와
같은 뿌리인데, 그때 지우기만 넣고 보내기를 빠뜨렸다.

이제 위줄에 보내기 키가 선다. **이름은 우리가 짓지 않는다** - 호스트가 말하는
`returnKeyType` 을 그대로 적는다(메시지 앱이면 보내기, 검색창이면 검색, 안 알려 주면
줄바꿈 화살표). 우리가 "보내기" 라고 지어 부르면 안 보내지는 앱에서 그 글자가 거짓말이 된다.

키 자리는 `[붙여넣기] [보내기] [지우기] [X]` 다. 보내기와 X 를 붙여 두지 않았다.
하나는 보내 버리고 하나는 다 지우는 키라, 잘못 누른 값이 양쪽 다 크다.

설정 > 키보드 레이아웃 > 표시 옵션에서 끌 수 있다(기본 켬).

### 둘. 잠근 단축어는 값을 고를 수가 없었다

> 一条加密短语解锁后的多条内容会同时都弹出，无法选择。

값이 여러 개인 단축어(콤보)는 좌우 분할 키로 값을 골라 넣는데, **잠긴 것은 그 분할 키에서
빠져 있었다.** 그래서 통짜 키로 떨어져 1번 값만 나가고 2번부터는 키보드에서 꺼낼 길이
아예 없었다.

이제 잠긴 콤보도 분할 키를 받는다. 고르는 일(오른쪽 화살표)에는 값이 필요 없으니 인증 없이
넘어가고, **값이 나가는 왼쪽만** PIN 을 받는다. 키캡에 값이 잠깐 비치는 연출은 잠긴 것에서는
끈다. 잠가 둔 값이 화면에 비치면 잠근 뜻이 사라진다.

같은 요청의 앞부분("Face ID 로 열게 해 달라")은 **만들 수 없다.** iOS 가 키보드 익스텐션에
`LocalAuthentication` 을 열어 주지 않는다. 근거와 판단은
`docs/postmortem/KEYBOARD_FACEID.md` 에 남겼고, 대신 PIN 판과 잠금 번호 설정에
"키보드에서는 Face ID 를 쓸 수 없다"를 한 줄씩 적어 두었다.

### 셋. 사진이 키보드에서만 안 붙었다

> can copy it from the app and paste it somewhere. However, cannot paste by using the keyboard.

키보드 익스텐션의 메모리 한도가 원인이었다. 사진을 원본 그대로 펼쳐서(3000x4000 이면 48MB)
클립보드에 얹고 있었는데, 그 한 장이 한도를 넘기면 iOS 가 익스텐션을 **조용히 죽인다.**
에러도 경고도 없이 "눌렀는데 아무 일도 안 일어남" 으로만 보인다. 앱에는 그 한도가 없어서
앱에서만 됐다.

이제 익스텐션은 사진을 펼치지 않는다. 그릴 때는 ImageIO 가 디코드 단계에서 줄여 주고,
클립보드에는 파일 바이트를 그대로 건넨다. 자세한 것은
`docs/postmortem/KEYBOARD_IMAGE_MEMORY.md`.

곁에서 같이 나온 것 하나. **글+사진 단축어를 앱에서 복사하면 사진이 사라지고 있었다.**
사진을 얹은 다음 글을 얹었는데, 클립보드는 새로 얹을 때마다 앞의 것을 버린다.
이제 한 항목에 두 표현을 함께 담는다.

### 넷. 함께 쓰는 앱

설정에 같은 사람이 만든 앱들을 소개하는 화면이 생겼다. 목록이 아니라 **이 앱이 등장하는
장면**부터 보여 준다("지원서를 넣는 날", "서류가 오가는 오후" 같은 것). 자기 자신은
목록에서 빠지고, 지금 기기에서 못 받는 앱은 그렇다고 말한다.

목록·문구·이야기는 LeeoKit(`LeeoFamilyCatalog`) 한 곳에 있어서, 앱을 새로 내면 LeeoKit 만
올려도 다른 앱들이 그 앱을 소개하기 시작한다.

## 심사·배포 메모 (내부)

### ⚠️ 실기기 확인 (보내기 키)

시뮬레이터로는 절반만 본다. 실제로 보내지는지는 남의 앱에서 눌러 봐야 안다.

1. 위챗·카카오톡·라인 입력창에서 단축어를 넣고 보내기 키를 누른다 → **메시지가 나가야 한다.**
2. 사파리 주소창에서 키 이름이 "이동하기" 로 바뀌는지, 검색창에서 "검색" 으로 바뀌는지 본다.
3. 메모장처럼 이름을 안 주는 곳에서는 줄바꿈 화살표로 서고, 강조색이 아니어야 한다.
4. 설정에서 끄면 키가 사라지는지, 켜면 다시 서는지 본다.

⚠️ 우리가 할 수 있는 것은 `"\n"` 을 넣는 것뿐이다. 리턴 키를 눌렀다고 호스트에 알리는 API 는
없으므로, 그렇게 안 만든 앱에서는 줄만 바뀐다. 설정 푸터가 그 몫을 말한다.

### ⚠️ 실기기 확인 (사진)

1. **아이폰 카메라 원본**(12MP)을 단축어에 붙인다. 작은 이미지로는 재현되지 않는다.
2. 다른 앱에서 키보드를 띄우고 그 키를 누른다 → 사진이 클립보드에 올라가야 한다.
3. 입력창을 길게 눌러 붙여넣는다 → 사진이 붙어야 한다.
4. 이미지 단축어를 여러 개 만들고 키보드를 오르내린다 → 키보드가 죽거나 깜빡이지 않아야 한다.
5. 글+사진 단축어를 **앱에서** 눌러 복사한다 → 사진과 글이 둘 다 붙을 수 있어야 한다.

### ⚠️ 실기기 확인 (잠긴 콤보)

1. 값이 셋인 단축어를 만들고 잠근다.
2. 키보드에서 오른쪽 화살표로 2번, 3번으로 넘긴다 → **인증을 묻지 않아야 한다.**
3. 왼쪽을 누른다 → PIN 을 묻고, 통과하면 **고른 그 값만** 들어가야 한다.
4. 화살표를 눌러도 키캡에 값이 비치지 않아야 한다.
5. PIN 판에 "키보드에서는 Face ID 를 쓸 수 없어 번호로 엽니다" 가 보이는지, 작은 기기
   (SE 계열)에서 숫자판이 잘리지 않는지 본다.

### 남겨 둔 것 (다음 판)

- **사진은 저장할 때 여전히 원본 PNG 다.** 읽는 쪽을 다 고쳐서 이제 죽지는 않지만,
  디스크와 iCloud 백업 용량은 그대로 크다. 줄여서 저장하면 되돌릴 수 없으므로
  (화질 손실) 사람이 정할 일로 남긴다. `CLAUDE.md` 의 "1024px · JPEG 0.7" 규칙과
  어긋난 채로 있는 것도 그때 같이 정리한다.
- `ClipKeyboardList.swift` 의 목록 카드도 원본을 펼치는 `loadImage` 를 쓴다.
  앱이라 한도에 안 걸릴 뿐, 같은 갈래다.
- `WhatsNewView` 는 아직 5.0.0(이름이 바뀐 것을 알리는 자리) 그대로다. 이번 판의
  새 기능을 그 시트로도 알리려면 내용을 새로 쓰고 `WhatsNewContent.version` 을
  같이 올려야 한다. 버전만 올리면 옛 안내가 다시 뜬다.
